# Техническая основа

Unity 6000.6.8f1, Universal 2D / URP, Input System, uGUI. Цель сборки — Windows x64. Версии сверять с `ProjectSettings/ProjectVersion.txt` и `Packages/manifest.json`.

## Запуск и сборка

Открыть `Assets/Golovomka/Scenes/Game.unity` и включить Play Mode. Основная сцена дополнительно загружает `PoliceStation.unity` и `Laboratory.unity`. Эти три сцены входят в список сборки. В `Laboratory` находятся комната 1, «Эстафета», испытание с двумя копиями и пустая комната за его дверью. Отдельная `Room02.unity` хранит исходную раскладку.

`EchoMvp` подключает готовые сцены и переключает видимость их корневых объектов. Точка появления читается из `PoliceStationLayout` для участка и из `LaboratoryRoom` для возврата по пульту. При входе в лабораторию начинается запись, при возвращении в участок текущая попытка сбрасывается. В `Room01Layout` поля `Door` и `Plate Overlay` связывают дверь и положение плиты со сценой. При отсутствующей сцене или обязательной ссылке Unity пишет ошибку в Console.

## Настройка комнаты лаборатории

20 ноября 2026 по просьбе автора комнаты 1 и 2 переведены на общий компонент `LaboratoryRoom` в сцене `Laboratory.unity`.

- `Room Number` — уникальный номер от 1 до 4. Он привязывает записи к комнате. Сохраняй номера существующих комнат.
- `Entrance` — точка прибытия по умолчанию и точка возврата по R, когда эта комната записана в пульте. Для прихода с другой стороны можно указать свою точку `Arrival` в переходе.
- `Camera Area` — границы кадра из `BoxCollider2D` с включённым `Is Trigger`. Если область не назначена, используется `Camera Size` с центром в позиции объекта комнаты. `Preview Width` расширяет кадр вправо.
- `Copy Limit` — число одновременно сохраняемых и воспроизводимых записей для этой комнаты. В комнатах 1 и 2 выставлена одна копия.
- `Passages` — переходы. `Marker` задаёт место активации, `Interaction Radius` — радиус действия E. При назначенном `Crossing Door` переход срабатывает при пересечении середины проёма в направлении `Cross To Right`. `Destination` задаёт комнату, участок, сообщение или экран завершения. Для комнаты укажи `Target Room`. Флажок `Sets Return Point` на автоматическом выходе требует пульт и сохраняет вход целевой комнаты как точку возврата. Иван продолжает идти с той же позиции.

Для новой комнаты добавь компонент на её корень, расставь маркеры и свяжи переходы в обе стороны. Настройки проверки пульта комнаты 1 и сигналы дверей комнаты 2 находятся в их механизмах.

Готовая папка Windows — `outputs/Golovomka-Echo-MVP`. Для передачи нужна вся папка. Архив не создаётся. [Инструкция к готовой сборке](../outputs/Golovomka-Echo-MVP/README.md).

`EchoMvpTools.Prepare()` пересоздаёт основную сцену и исходные настройки. Для обычного редактирования сохранять существующие сцены.

Unity CLI установлен в `%LOCALAPPDATA%/Unity/bin/unity.exe`. Указывать полный путь проекта и сверять версию открытого Editor.

```text
unity recompile --project-path <полный путь проекта> --format json
unity command script eval --project-path <полный путь проекта> --code "return EchoMvpTools.Verify();" --format json
unity command build run --project-path <полный путь проекта> --target StandaloneWindows64 --output-path outputs/Golovomka-Echo-MVP/Golovomka.exe --confirm true --format json
unity command build status --project-path <полный путь проекта> --format json
```

Сборка асинхронна. Результат проверять через `build status`.

## Графика и камера

- В сцене `Game.unity` объекты `Main Camera` и `Ivan` доступны в Hierarchy вне Play Mode. Компонент `EchoMvp` хранит ссылки на камеру и SpriteRenderer Ивана. Чтобы применить ручную позицию и Orthographic Size в игре, отключить `Auto Fit Room` у `EchoMvp`.
- Масштаб Ивана задаётся в его Transform, скорость — через `Move Speed` у `EchoMvp`. В первой комнате применяется множитель 0,65 к масштабу Ивана и копий. Стартовые позиции задаются маркерами раскладок. В редакторе виден кадр `IvanIdlePreview`, полученный из игрового листа. При запуске используется штатная анимация.
- В участке ортографическая камера в `EchoMvp.Viewport.cs` показывает помещение целиком. В лаборатории камера держит общую высоту и плавно следует за Иваном только по X при выходе из центральной области кадра. Границы вычисляются из активных `LaboratoryRoom`, включая правый запас `Preview Width`. При переходе между комнатами кадр сохраняет непрерывность. При возврате времени он сразу переносится к точке появления Ивана.
- В Inspector у `EchoMvp` для примерки доступны `Laboratory Dead Zone Width` (0,4 ширины кадра) и `Laboratory Camera Smooth Time` (0,22 с). PixelPerfectCamera отключён. Его временные параметры — 16 PPU и 480×270. Спрайты используют Point, движение привязано к сетке 1/16.
- HUD использует CanvasScaler 1280×720 и расположен поверх комнаты. Подписи мира ограничены по вертикали viewport 0,14–0,82.
- Герой и копии используют `Resources/Art/IvanOfficerWalk.png`. Импорт Default, Point, Read/Write, без mipmaps и сжатия. Нарезка и выравнивание кадров по подошвам — в `EchoMvp.Officer.cs`.
- В прототипе используется Modern Interiors Free v2.2 от LimeZu. Лицензия для некоммерческого использования лежит в `Assets/Golovomka/Resources/Art/LICENSE-LimeZu.txt`.

## Столкновения

По указанию автора от 20 ноября 2026 самостоятельные невидимые блоки для стен не добавляем. Коллизия должна соответствовать видимым стенам, предметам и дверям.

20 ноября 2026 по просьбе автора участок и лаборатория перешли на препятствия `Collider2D` из активной игровой сцены. Контроллер проверяет хитбокс ног размером 0,44 × 0,28 вдоль каждого шага. У препятствий выключен `Is Trigger`. Пол и триггеры свободны для движения. Внешний контур участка задаётся отдельными коллайдерами в сцене.

Хитбоксы мебели настраиваются через **Edit Collider**. В лаборатории слои «Стены» и «Задняя стена» используют `TilemapCollider2D`. С 20 ноября 2026 на каждой игровой двери один `BoxCollider2D` на объекте с `SlidingDoor`. Он движется вместе с дверью и служит и границей проёма, и препятствием. Открытый проход оставляет его триггером. Если сигнал пропал, пока Иван в проёме, коллайдер становится препятствием после выхода. Окно проёма остаётся визуальной маской. После правок проверять проходы в `Game`.

## Сохранение прогресса

`EchoHistory` пишет `echoes-mvp-v3.json` в `Application.persistentDataPath`. Сохраняются завершённая запись, номер цикла, этапы знакомства с пультом и номер комнаты для возврата по R. При замене файла создаётся резервная копия `.bak`. Продолжение начинается у телефона. Формат v3 принимает прежние сохранения. Старый номер пройденной комнаты преобразуется в точку возврата следующей комнаты.

Старые записи с `room = 0` читаются как общие. При добавлении локальной записи прежний общий маршрут, содержащий кадры этой комнаты, удаляется целиком, включая кадры других комнат.

## Проверка

`EchoMvpTools.Verify()` проверяет интерполяцию, конец записи, лимиты, сохранение и резервную копию.

`EchoIntroductionVerification.VerifyPlay()` запускать в отдельном сеансе Play Mode. Сценарий подставляет тестовые состояния, проверяет автоматические переходы, положение Ивана, новое место появления по R, закрытие дверей и открытие общей двери двумя копиями. Сохранение пишет в `work/intro-verification-save.json`.
